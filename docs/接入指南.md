# 产品接入指南

给想用本仓库构建的新产品看的一份完整说明。现有两个参考实现：`pdf_reader`（纯 .NET）和
`invoice_renamer`（Tauri + .NET，带原生外壳）。

---

## 一、先理解职责边界

```
build_action 仓库            产品仓库（私有，code.zsrhkj.com）
──────────────────           ──────────────────────────────
.github/workflows/*.yml  ──►  CI 内 clone 下来，跑产品自己的 scripts/
products/<name>/
  ├── product.env              scripts/build-*.sh / *.bat
  └── README.md                scripts/upload-oss.sh
                               scripts/deploy.env（凭证，不进 Git）
```

三条铁律，别越界：

1. **构建逻辑永远留在产品仓库的 `scripts/`**，本仓库不复制一份。产品仓库自己 `bash scripts/xxx.sh`
   能跑通，CI 就只是把它搬到 runner 上跑。
2. **本仓库只放 workflow 与配置**（非敏感参数进 `product.env`，敏感信息进 GitHub Secrets）。
3. **CI 不碰 OSS、不登记版本**。CI 只产出 artifact；上传和 hub.zsrhkj.com 版本注册在本地做
   （`gh run download` + 产品自带的 `upload-oss.sh`）。这样 CI 里不需要任何发布凭证，也快得多。

> 为什么要有这个仓库：源码托管在自建私有 Git 平台，没有 Actions runner，产品仓库自己跑不了 workflow。

## 二、接入三步

### 第 1 步：让产品仓库"具备被 CI 跑的条件"

在动手写 workflow 之前，先确认产品仓库满足下面五条。不满足的话，先改产品仓库，不要试图在 CI 里绕过。

| 条件 | 说明 |
|------|------|
| **一段式构建脚本** | 每个平台一个入口（`scripts/build-linux.sh` / `scripts/windows/build-installer.bat`），从头跑到尾，**不许有交互输入**（CI 里没人按键），靠退出码判断成败（`set -euo pipefail` / `exit /b 1`） |
| **版本号单一来源** | 写在一个文件里，脚本自己解析（csproj 的 `<Version>` / `tauri.conf.json` 的 `version`）。CI 也要读同一个来源生成 tag |
| **产物落到固定路径** | workflow 的 artifact glob 必须能匹配到。把路径写进产品 README |
| **依赖能自己装或能列清** | 脚本自己装最好；否则在 `products/<name>/README.md` 里列出来，由 workflow 装 |
| **构建不依赖本机绝对路径** | 像 `/Volumes/Private/LB/...` 这种只在开发机上存在的路径不能出现在构建路径里 |

### 第 2 步：在 build_action 里加三个文件

```bash
products/<name>/product.env     # 非敏感配置
products/<name>/README.md       # 平台、产物、所需 secrets、已知风险
.github/workflows/<name>.yml    # workflow（必须平铺，子目录里不会触发）
```

最小改法：**拷 `products/pdf_reader/` + `.github/workflows/pdf_reader.yml` 改四处**——
源码仓库地址、构建脚本路径、runner/工具链 setup、artifact 路径。

### 第 3 步：配 Secrets

在 **build_action** 仓库 Settings → Secrets and variables → Actions 里配（**不是**在产品仓库配）：

| Secret | 何时需要 |
|--------|----------|
| `REPO_USER` / `REPO_TOKEN` | 所有产品共用（clone 私有源码）。用通用的 token，确认有读该产品仓库的权限 |
| `OSS_KEY_ID` / `OSS_KEY_SECRET` | **本项目模式下不需要**（CI 不上传 OSS）。只在产品改为 CI 内上传时才需要 |

## 三、`product.env` 字段

```ini
PRODUCT_NAME=invoice_renamer                                  # 产品标识，与目录名、workflow 名一致
REPO_URL=code.zsrhkj.com/zsrhkj/InvoiceRenamer.git            # 不带 https:// 前缀
DEFAULT_REF=master                                            # 默认分支
PLATFORMS=win-x64,linux-x64                                   # 要构建的平台
BUILD_LINUX=scripts/build-linux.sh                            # 各平台构建入口
BUILD_WIN=scripts/windows/build-installer.bat
ARTIFACT_GLOB=src-tauri/target/release/bundle/**,artifacts/windows-installer/**
VERSION_SOURCE=src-tauri/tauri.conf.json                      # 版本号来源
DOTNET_VERSION=8.0.x
NODE_VERSION=22                                               # 需要 node/npx 的产品才写
RUST_TOOLCHAIN=stable                                         # 需要 Rust 的产品才写
```

## 四、workflow 模板要点

完整实例见 `.github/workflows/pdf_reader.yml`（纯 .NET）和 `.github/workflows/invoice_renamer.yml`（Tauri）。

### 4.1 平台过滤（照抄）

`workflow_dispatch` 的 `platforms` 输入 + 一个 `Resolve run flag` 步骤，让没选中的平台**跳过 job 内所有步骤**
而不是整个 job 不启动——这样 matrix 结构保持简单，也不需要写 `if` 到处塞。

```yaml
- name: Resolve run flag
  id: flag
  shell: bash
  run: |
    want='${{ github.event.inputs.platforms }}'
    [ -z "$want" ] && want=all
    if [ "$want" = "all" ] || [ "$want" = "${{ matrix.label }}" ]; then
      echo "run=true" >> "$GITHUB_OUTPUT"
    else
      echo "run=false" >> "$GITHUB_OUTPUT"
    fi
```
之后每个步骤都带 `if: steps.flag.outputs.run == 'true'`（再加平台条件 `&& matrix.label == 'win'`）。

### 4.2 clone 私有源码（照抄，别改）

用 git credential helper 把 token 注入内存，**不要**把 token 拼进 clone URL（会进进程列表和日志）：

```yaml
run: |
  git -c credential.helper= \
      -c credential.helper='!f() { echo "username=$REPO_USER"; echo "password=$REPO_TOKEN"; }; f' \
      clone --depth 1 -b "$ref" "https://${REPO_PATH}" "$SRC_DIR"
```

### 4.3 工具链 setup

| 栈 | 需要的步骤 |
|----|-----------|
| 纯 .NET | `actions/setup-dotnet@v4`（`8.0.x`） |
| Node 工具链 | `actions/setup-node@v4`（需要 `npx` 的产品，例如 Tauri CLI） |
| Rust / 原生外壳 | `rustup toolchain install stable --profile minimal --no-self-update && rustup default stable`（runner 自带 rustup，不用第三方 action） |
| Windows 安装包 | `dotnet tool install --global wix --version 5.0.2` |
| Linux 桌面外壳 | `apt-get install libwebkit2gtk-4.1-dev libgtk-3-dev libayatana-appindicator3-dev librsvg2-dev libssl-dev build-essential rpm` |

### 4.4 artifact 只收最终安装包

```yaml
path: |
  src/.../bundle/deb/*.deb
  src/.../bundle/rpm/*.rpm
  src/.../bundle/tar/*.tar.gz
  src/artifacts/windows-installer/*/InvoiceRenamer-Setup-*.exe
if-no-files-found: error
```

两个要点：
- **glob 只匹配文件**，写成目录名会把整个解包目录（几百个 DLL）也收进去，下载极慢。pdf_reader 专门有个
  commit 就是为这个（"artifact 只收安装包，剔除解包目录加速下载"）。
- `if-no-files-found: error` 是"**一个都没匹配到**才报错"。可以把所有平台的 glob 都列上，
  每个 runner 只命中自己那份，互不影响。

### 4.5 版本号 → tag

从 `VERSION_SOURCE` 解析版本，`workflow_dispatch` 时用 `tag_name: format('<产品>-v{0}', version)`，
打 tag 触发时直接用 `github.ref_name`。

### 4.6 runner 计费

| runner | 计费倍数 | 说明 |
|--------|----------|------|
| `ubuntu-latest` | 1x | 最快最省，**首次验证永远先跑 Linux** |
| `windows-latest` | 2x | 安装包链路最复杂 |
| `macos-latest` | 10x | 不需要就别加进 matrix |

## 五、本地发布（OSS + hub 注册）

Action 跑绿后，在**有产品仓库和 `scripts/deploy.env` 的开发机**上执行：

```bash
cd /Volumes/Private/LB/<产品>       # 产品仓库

# 1) 拉最近一次成功构建的产物
RUN=$(gh run list --repo liub-a/build_action --workflow <name>.yml \
        --status success -L 1 --json databaseId --jq '.[0].databaseId')
gh run download "$RUN" --repo liub-a/build_action -D /tmp/artifacts

# 2) 逐个上传 + 登记（平台码必须与客户端检查更新时用的一致！）
bash scripts/upload-oss.sh <platform> /tmp/artifacts/.../<安装包>

# 只上传不登记：--skip-publish    只打印不执行：--dry-run
```

平台码是最容易出错的一环：**OSS 上传用的平台码、hub 登记的平台码、客户端 `UpdateService` 检查更新时
传的平台码，三者必须完全一致**（例如 `win-x64`、`linux-x64-deb`）。不一致的表现是"传上去了但客户端永远
检测不到更新"。

## 六、常见坑

| 坑 | 表现 | 处理 |
|----|------|------|
| `REPO_TOKEN` 权限不足 | clone 时报 403/认证失败 | 换通用的 token，或给它加该仓库读权限 |
| artifact 体积巨大 | 下载几十分钟 | glob 只收安装包，别把解包目录收进去 |
| 构建脚本要交互输入 | CI 卡住直到超时 | 产品脚本加非交互模式（如 `-y` / `--yes`） |
| 版本号两处不一致 | tag 与安装包版本对不上 | 只认 `VERSION_SOURCE`，其余地方引用它 |
| WiX 大版本不对 | 品牌安装包直接报错 | 必须是 5.x（6/7 不兼容，7 还要接受付费协议） |
| Linux 缺 WebKitGTK 4.1 | 外壳编译或运行失败 | runner 装 `libwebkit2gtk-4.1-dev`；只带 4.0 的旧系统装不上 |
| net48 引用程序集缺失 | 编安装界面报缺引用 | `choco install netfx-4.8-devpack -y` |
| 把 CI 当成能跨平台编译 | 想在 mac 上出 Windows/Linux 包 | **不行**：Tauri 外壳链接系统 WebView、WiX 必须在 Windows。CI 的价值正是每个平台用原生 runner |
| 在 CI 里配发布凭证 | 泄露面变大 | 按本项目模式：CI 不上传，凭证只留在开发机的 `deploy.env` |
